# 正式分析 v3：证据改为编号片段运输

## 为什么不再续补 v2

v2.10 的六个校准槽位全部首试通过，但第一个正式单元
`ENCODE_V210_M1_S2_C01` 连续两次失败。两次 Claude CLI 都正常返回了
结构化 JSON，但每次都有 7 条决定性证据不是原回答中的连续字串。
父版因而没有任何有效正式编码，也没有编码阶段清单。

这说明问题不是再补一句“请精确抄原文”就能稳定解决。让模型同时做语义
判断和长文字符级转录，把两种不同能力绑在了一起。

## v3 的唯一实质改动

程序先按换行和中英文的句号、问号、感叹号、分号、逗号、冒号，把每份
原回答机械切成连续原文片段，并标为 `A-E001` 这样的编号。模型只返回
`evidence_span_id`，不再手抄证据。程序根据编号取回冻结原文和出现次数，
然后展开成与 v2.10 完全相同的规范编码结构。

身份显形证据同样改为片段编号。菜单、方向标签、数学/非数学账、成对判决、
共识规则、复核和统计算法全部不变。

## 新的校准条件

旧合成回答只有几十字，而 48 份正式回答的字符数范围为 865—2527，中位数
1672.5。v3 保留原金标准差异，同时向 A/B/C 机械追加完全相同的长度
压力段三次。六份实际校准输入长度为 1765—1819 字符，中位数 1814；每份有
104—109 个可引用片段。这同时测长文片段定位和相同方向多次出现时的去重。

六个槽位必须在这份长合成材料上全部首试通过；任一失败，不得接触正式
回答。

## 边界与利益申报

- 这是看到已生成样本之后的分析运输修订，不得写成从头到尾未改的完整预注册。
- 分隔符决定了证据片段的最小粒度；它解决字符级抄录，不保证每个语义方向都
  恰好有一个完美的片段。
- 同一片段可被多个不同方向引用；同一菜单方向在一份回答中仍最多登记一次。
- 父版失败已经暴露了第一个正式块的文字给执行方，但没有任何有效票。v3 的分割规则
  是对所有回答一视同仁的机械变换，不根据臂、题目或预期结果改变。

## 不变的资源闸门

新运行目录独立计数：6 次长合成校准 + 48 次主编码 + 至多 6 次复核 +
8 次重试余量，总请求尝试上限仍为 68。父版任何校准票和失败票都不复用。
