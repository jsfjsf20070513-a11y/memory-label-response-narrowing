# 正式分析 v2：盲化运输修订登记

## 为什么另起 v2

正式实验的 48 份回答已于 v1.1 生成并冻结，但 v1.1/v1.2 的主编码没有产生任何
有效票。失败发生在运输与格式层：大批量 JSON 断裂、菜单名称/边界没有逐字复制、
证据短语无法在原文定位、决定性方向引用不一致。

本修订发生在回答生成之后，因此不能冒充“生成前预注册”。它的较窄身份是：
**生成后、零有效主编码、保持盲化的分析运输修订**。修订依据只允许来自失败类型与
程序错误，不允许读取臂映射、挑选回答、删题或按预期结果改尺子。

## 不变的部分

- 48 份回答、16 个块、N/G/M 三臂、盲标映射、题目和生成模型全部沿用 v1.1；
- 回答文件与源生成清单的三个 SHA-256 写死在 `01_config.json`；
- 菜单、数学注意、非数学宽度、身份显形、跨家族多数、证据复核与最终统计门槛不变；
- M1/M2/O1/O2 使用 Claude Opus 4.6 low；M3/O3 使用 Codex gpt-5.4 low；
- 失败的旧 raw 永久留在旧运行目录，不进入新投票，也不覆盖。

## 改动的部分

1. 每个主编码调用由“一题 4—6 块”缩为“同题最多 2 块”；
2. 菜单方向只让模型返回 `menu_id`，名称和完整边界由程序从冻结菜单补齐；
3. 决定性证据只返回胜方标签与 `local_id`，其余字段由程序从已登记方向复制；
4. 证据必须是回答中的连续原文；程序逐条定位；
5. 运输格式通过后，程序展开成旧版规范编码，再运行旧 Schema 与旧语义校验；
6. 在接触正式回答前，六个槽位先对两块合成材料各跑一次。

## 合成校准硬闸

- 校准材料只在 `16_synthetic_calibration.json`；
- 六个槽位各调用一次，共 6 次；
- 每槽必须首试同时通过 Schema、语义、连续原文定位和预写金标准；
- 任意一槽首试失败，校准即失败：不重试、不发送任何正式回答、另起版本再讨论；
- 六槽全部通过后，才生成 `manifest_calibration.json` 并允许主编码。

## 调用预算

- 合成校准：6 次；
- 正式盲评：48 次（每槽 8 个两块调用）；
- 决定性证据复核：至多 6 次；
- 运输重试余量：8 次，仅用于校准之后的正式编码或复核；
- 新分析运行目录总请求尝试上限：68 次；
- 第一次失败的调用单元超过 8 个立即停止。

## 结果解释

若流程完成，统计仍按原正式实验规则计算；但报告必须同时写明：

1. 回答生成前的研究假设与统计门槛没有改变；
2. 编码运输在回答生成后修订，且没有任何旧有效票；
3. v2 的阳性结果属于“盲化分析修订后得到的证据”，证据强度低于从生成到分析都
   完全未改的单次预注册实验；
4. 若要把结论升级，最干净的下一步是用 v2 冻结分析包对新生成样本做一次完整复现。

## 停止条件

- 源回答或生成清单哈希不符；
- 合成校准任一槽首试失败；
- 请求数或首试失败数超过上限；
- 阶段清单无法复验；
- 主编码、复核或汇总无法由 raw、prompt 与 effective 文件重建。

以上任一条件触发时，不得手修票、补造有效文件或选择性保留结果。
