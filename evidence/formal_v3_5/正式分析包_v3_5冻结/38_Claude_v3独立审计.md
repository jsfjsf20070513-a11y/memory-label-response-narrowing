# Claude Code / Opus 4.6 对正式分析 v3 的独立审计

## 审计方式

- 模型：Claude Code `claude-opus-4-6`，low；
- 权限：只读，不编辑文件，不调用其他模型；
- 输入：v3 修订、运输代码、Schema、两份提示、长合成材料、单测、复现文档、
  闸门和 v2.10 父运行 raw；
- 审计重点：原文子串和标签隔离、规范结构不变、长校准、父版零有效票、调用预算与新闸门。

## 第一轮结论

**PASS。**

审计方独立确认：

1. `re.finditer` 产生的每个片段都是原回答的连续子串；`validate_transport`
   在当前 A/B/C 标签的片段表中查编号，不能串标签。
2. `expand_transport` 只取回冻结原文、出现次数和冻结菜单边界；判决、标签、
   身份显形与下游规范结构不变，展开后仍走旧 Schema 和旧语义校验。
3. 父版请求数确为 6 校准 + 2 失败正式尝试，无 `manifest_coding.json`、
   无有效正式编码；v3 的 68 次新目录上限分解正确。
4. 片段编号从结构上消除了 v2.10 的“模型手抄证据不是连续原文”失败类型。

第一轮唯一值得处理的非阻塞限制是：当时合成校准长度只覆盖正式回答下界，
没有覆盖中位长度。

## 根据审计收紧后的短复核

执行方没有把长度缺口留到报告里，而是把同一中性压力段在 A/B/C 中对称重复
三次，使校准材料变为 1765—1819 字、104—109 个片段。这一改动后，同一
Opus 4.6 审计会话再做短复核。

复核结论仍为 **PASS**：

- 重复段在同一块的 A/B/C 中完全相同，不改金标准差异；
- 不含身份标记，不引入 A/B/C 不对称；
- 反复出现的相同方向同时对“同一菜单方向最多登记一次”施加去重压力；
- 长度与片段数已进入正式回答的中位区间，无新阻塞。

## 仍然保留的边界

校准只使用 S2 主题，未覆盖 S8/S10 的专有内容结构。这不影响机械分段和编号
取回的通用性，但意味着校准不是对三道题语义难度的完整拟真。本项作为报告限制，
不作为冻结阻塞。
