# Claude Code / Opus 4.6 对 v3.1 的独立审计

## 审计方式

- 模型：Claude Code `claude-opus-4-6`，low；
- 权限：只读，不编辑文件，不调用其他模型；
- 审计材料：v3.1 修订、父运行、运输与复算代码、分表 Schema/提示、单测、复现说明和闸门；
- 主要反证目标：是否选择性捡票、父票是否真能从 raw 复算、分表是否会静默改方向顺序或统计输入。

## 结论

**PASS。**

审计方确认：

1. 父版事实链对上：六槽校准通过，25 次请求由 6 校准、17 有效正式 raw 和 2 份
   同类格式失败 raw 组成；无完整 `manifest_coding.json`，无解盲汇总。
2. 只复用完整 M1/M2、丢弃孤立 M3 是干净的整槽边界。停止原因是运输格式，
   与臂差异无关；执行方当时没有解盲或汇总。
3. 54 件复用证据的联合哈希和逐单元 `prompt → raw → transport → canonical`
   复算足以锁定复用内容；最终 canonical 还做字节级比对与语义复验。
4. `menu_directions` 的 Schema 根本没有 `name/definition`，`extra_directions`
   根本没有 `menu_id`，从结构上排除了 v3 的旧错误。
5. `normalize_transport` 按 local_id 数值合并两表，随后仍检查必须恰好为
   `d1,d2,...`；重号、跳号或两表各自从 d1 开始都会被拦下，不会静默重排成合法票。
6. 规范编码和下游统计输入不变；新目录 `1 + 32 + 6 + 8 = 47` 的调用闸门与阶段清单闭环。

## 仍须披露的限制

- v3.1 是看到 v3 运输失败后的生成后分析修订；
- 复用依赖父运行目录可读，但篡改会被预存联合哈希拦下；
- 编码模型家族仍只有 Claude 与 Codex 两家，跨家族同意是保守护栏，但不排除两家共享偏差；
- M3 新分表只校准一次，首试失败就停止，这是保守闸门，不是可选择重试的调参机会。
