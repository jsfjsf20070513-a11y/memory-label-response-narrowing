# 正式分析 v3.5：额度中断后的最小续跑

## 现场事实

v3.4 成功完成 M2、M3 的五批复核并各自通过完整任务集校验。随后 O1 第一批尝试两次，
两次都由 Claude Code 在推理前返回会话额度 429；记录中 `input_tokens=0`、
`output_tokens=0`。v3.4 因此没有 `manifest_review.json`、`summary.json` 或揭盲结果。

## 唯一修订

新运行目录复建并复验完整的 M1/M2/M3，继续跑尚未产生任何判断的 O1/O2/O3。后者仍
按 v3.4 已冻结的每槽五批、每批最多 30 任务、任务 ID 作为 Schema 必填键的方式执行。
没有重新分批，没有换模型，没有改提示、任务、判断或汇总。

O1 的两份 429 raw 只用于证明中断发生在推理前，不进入结果；不存在从失败输出中挑取
可用判断的路径。

## 请求预算

v3.5 新请求为 15 个主调用加 8 次重试，硬上限 23。此前实际请求数为 36+7+12=55，
所以整个正式分析链的最坏累计为 55+23=78，正好落在用户已经批准的 78 次范围内。
程序测试同时固定新槽集合、五批计划和这个累计上限。

## 可复现边界

`prepare` 逐层复验 v3.2 编码、v3.3 M1、v3.4 M2/M3 和 O1 额度失败。复用的是完整槽，
不是单条有利判断。`review` 只开放 O1/O2/O3；`aggregate` 仍走原冻结汇总器。任何父包、
父运行状态、有效复核证据束或 429 raw 哈希不符，续跑都失败关闭。

## 局限

M1 的数组运输与其余五槽的任务键固定运输不对称；M1、M2/M3、O1/O2/O3 又分属三次
运行。方法判断相同，完整性均复验，但报告必须披露这种实现和时间上的不对称。本修订
只处理额度中断，不提高当前材料的证据等级。
