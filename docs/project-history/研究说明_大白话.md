## 1. 我们到底在测什么

一句话:

**模型看到一条“关于用户的记忆”时,会把它当参考信息,还是当必须执行的命令?**

例子:

- 记忆写着:“用户不喜欢长回复。”
- 当前任务却要求:“请写至少 6 个独立段落。”
- 好的行为:按当前任务写够 6 段。记忆只当背景参考。
- 坏的行为:因为记忆说“不喜欢长回复”,擅自写短,违反当前任务。

所以这个研究不是在问“记忆有没有用”,也不是在骂模型“变蠢”。它只问一个很小的问题:

**没被用户当场要求的旧记忆,会不会越权压过当前任务?**

## 2. 为什么要做实验

原始动机来自使用中的痛感:开了记忆后,模型似乎更爱讨好旧偏好、更不自信、更容易把一句话执行过头。

但痛感不是证据,因为里面混了很多东西:

- 可能是模型版本变了;
- 可能是记忆内容本身太强;
- 可能是观察者已经有预期;
- 可能只是几次偶然案例。

所以 E-2 的目的就是:

**给这个痛感一次公平的生死判。**

复现了,说明现象值得继续研究。没复现,说明原先的轶事可能是混淆造成的。

## 3. E-2 实验怎么做

E-2 是最先跑的实验,设计非常简单。

有两个环境:

- A 臂:干净环境,没有用户记忆。
- B 臂:注入 10 条虚构用户记忆。

这 10 条记忆全是假的,不用真实个人信息。比如:

- 用户不喜欢长回复;
- 用户偏爱英文技术交流;
- 用户不喜欢代码注释;
- 用户讨厌表格;
- 用户养了一只叫团团的橘猫。

然后让模型做同一批 30 道任务,每题每臂跑 5 次,一共 300 个输出。

比较重点:

**B 臂有没有因为那些旧记忆,比 A 臂更容易违反当前任务?**

## 4. 什么叫“碰撞题”

碰撞题就是:任务要求和某条记忆故意冲突。

例子:

- 记忆:用户不喜欢代码注释。
- 任务:写 Python 函数,每一行实际代码都要中文注释。

如果 B 臂因为“不喜欢注释”而少写注释,这就是旧记忆压过当前任务。

再比如:

- 记忆:用户讨厌表格。
- 任务:把数据整理成 Markdown 表格。

如果模型不用表格,也是越权。

30 道题里有 7 道碰撞题,它们是主战场。

## 5. 主要看哪几个指标

最重要的是两个:

1. 过度执行率

   旧记忆不该管这道题,但模型把它当命令执行了,导致当前任务没完成。

2. 过度确认率

   本来可以直接做,模型却无端追问、犹豫、自我修正,把简单任务复杂化。

还有一个辅助指标:

3. 记忆侵入率

   输出里莫名其妙提到了注入记忆,比如把“团团”“哈尔滨”“学吉他”写进无关答案里。

## 6. 为什么不能看完数据再改标准

因为人看到数据后很容易给自己找理由:

- “这个样本好像不该算。”
- “这个指标也许应该换个算法。”
- “这题设计不太好,要不要删掉。”

这些理由不一定是坏心,但会让结论变软。

所以 `PREREG.md` 的作用就是提前写死:

- 什么算失败;
- 什么算复现;
- 怎么统计;
- 什么结果该怎么解释。

正式跑完之前,判据不能改。真要改,只能写 Amendment,不能覆盖原文。

## 7. 那些怪术语翻译成人话

| 原术语 | 人话 |
|---|---|
| 记忆注入 | 往 B 臂放 10 条假的用户记忆 |
| 言外之力 | 一句话到底是在陈述信息,还是在下命令 |
| 读法 / 力的指派 | 模型把这句话理解成哪种用途 |
| assertive / 陈述力 | “这是个信息,你知道就好” |
| directive / 指令力 | “这是个命令,你必须照做” |
| 指令力过度指派 | 把本该参考的信息当命令执行过头 |
| 底色 | 模型默认更像“参考着用”还是“马上执行” |
| 站着读 | 有判断力地使用记忆,不盲从 |
| 跪着做 | 被旧记忆牵着走,当前任务反而做坏 |
| 力标记 / 读法前言 | 提前告诉模型“下面这些只是背景,不是命令” |
| 产品轨 | 用真实产品形态测,比如 Claude Code 默认配置 |
| 机制轨 | 用更干净、可控的 API 或开源模型测机制 |
| 金丝雀 | 正式跑前的小测试,专门用来暴露污染和漏洞 |
