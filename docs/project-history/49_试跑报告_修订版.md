# 49 · 极小试跑报告（修订版）

> 日期：2026-07-14。替代 47 号作为后续引用入口；47 号原样保留，逐项更正依据见 48 号。
> **PILOT_ONLY：**这轮只检查题目、尺子和流水线能否工作。臂间差异只用于选下一步，不是“数学身份让回答变窄”的证据。

## 一句话结论

流水线最终跑通，自动编码尺子能稳定产出结果，但也暴露了两个真风险：编码者从不说“判不了”；菜单会提高证据一致性，也可能诱导编码者硬找方向。试跑里唯一反复出现“更数学且其他方向更少”形状的是推荐系统题 S8'，所以正式实验应检验这一形状能否转移到**没在试跑里用过的新题**，不能继续拿 S8' 自证。

## 这轮真正证明了什么

冻结题面、两套编码办法、票型规则、追加规则和汇总程序能在订阅通道上走完，并得到可复算结果。Sol 独立重跑后，`summary.json`、`audit.json` 与现存产物逐字节一致；冻结包 33 项测试和完整性核验全部通过。

它没有证明数学身份导致回答变窄。每对只有一份生成样本；订阅封装无法锁温度和长度；编码者是自动测量，不是人类判官；流程经历过运输修正、窄引号归一和一次复核通道替换。Claude 相关调用使用 `claude-fable-5 --effort low`，Codex 使用 `gpt-5.4 low`，这只是省额度的试跑配置，正式实验不应自动继承。

## 流程与成本

研究流水线共有 **47 次请求尝试**：45 次有原始请求包，2 次 v2.2 未留原始包；其中 4 次在推理前被额度拒绝。一个 `M1_append_recovered.json` 只是恢复记录，不是新调用。这个数字不含 Fable/Sol 在外围做方法审核的会话。

流程属于“跑通但有伤痕”：主要问题是结构化输出和订阅通道运输；此外 v2.5 做过窄引号归一，O3 复核改走 Claude。全部偏离均已追加登记，没有覆盖旧史。

## 尺子表现

- 84 张个体主账票中，“无法判断”为 0；组内多数层面也没有无多数分歧；
- 一致性哨兵 0、Schema 错误 0、映射软错误 0；
- 自动编码者从不认怂既可能表示题目清楚，也可能表示它们过度自信。正式实验必须先用故意难判的哨兵检查这一点；
- 硬幻影 6 例，六例都来自 Markdown 加粗标记打断连续字符串。后续只允许可审计的 `**` / `__` 去标记定位，不扩成任意标点或空格归一。

## 菜单法与开放法

菜单组证据收敛率为 `0.5999`，开放组为 `0.3162`；语义幻影分别为 `10/257 = 3.9%` 与 `0/271 = 0%`。冻结赛马规则仍判“未分胜负”。

人话解释：菜单让三名编码者更容易看到同一处，但也可能让他们拿着目录去原文里硬配。这个小样本只构成风险信号，不能说菜单法已经被判有罪。正式实验保留两种办法；菜单判决必须接受语义复核，开放判决也用同样的证据复核规则。

## 正式实验必须继承的纪律

1. 先用难判哨兵检验编码者是否真的会说“无法判断”；
2. 菜单与开放两法并行，只有两法同向才进入主结论；
3. 决定主账胜负的证据必须接受对称的语义复核；
4. 硬幻影定位只窄修 Markdown 强调标记；
5. 增加“普通本科生”中间臂，分开“系统里出现了一条背景”和“数学标签本身”；
6. S8' 不进入主检验，只做登记后的复现；
7. 正式生成不用 Fable low。经本机真实用量复核，正式主生成最终改为用户最喜欢的 `claude-opus-4-6` + 产品 `Default` 推理强度；02 号旧决定被 03 号更正。

试跑至此关闭，不重跑；正式实验另立预注册、另生全新回答。
