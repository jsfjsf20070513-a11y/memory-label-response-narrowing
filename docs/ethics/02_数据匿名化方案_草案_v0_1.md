# 实验二数据匿名化方案(草案 v0.1)

> 2026-08-13 起草。对应 Issue #12 承诺与披露登记 D10。沿用实验一人类盲判已验证的
> 分区做法(管理员私有目录 + 仓库只存脱敏层),并吸收红线审计(2026-07-29)与
> E4 系列教训(提交元数据也是泄露面)。
>
> **状态:草案。** 收集平台(§4)与保存期限(§6)待 Q2 伦理路径确认后定稿。

## 1. 三层分区(硬边界)

| 层 | 放什么 | 在哪里 | 红线 |
|---|---|---|---|
| **管理员私有层** | 原始问卷(含自由文本原词)、同意/授权记录、参与码↔身份映射(如存在)、招募沟通记录 | 负责人本机离线目录(沿用`管理员私有_v0_1/` 模式,另建实验二子目录) | 永不提交、永不外发;不进任何云盘 |
| **仓库脱敏层** | 参与码级选择数据、经审查的理由摘录或编码、汇总统计、分析脚本 | 本仓库 | 入库前必须过 §5 双重检查 |
| **发表层** | 聚合统计、匿名引用的理由片段 | 论文 | 只从脱敏层取材,不回到私有层 |

## 2. 参与者编码

- 每名参与者分配随机参与码(建议格式 `E2-P##`,发放顺序与编码顺序解耦,
  防止"第一个来的是 P01"这类顺序推断);
- 参与码在招募时发给本人,用于撤回;
- **默认不建立身份映射**:若招募方式允许(如现场匿名发放),负责人一侧也不记录
  "谁拿了哪个码",撤回凭码即可执行。若招募方式必须可联系(如线上定向发送),
  映射表只存管理员私有层。

## 3. 授权与撤回的记录(D10)

- 同意记录(线上勾选导出 / 纸质签码扫描)存管理员私有层,与问卷数据同期限保存;
- 撤回执行流程:收到撤回请求 → 按参与码删除私有层原始记录与脱敏层对应行 →
  在仓库登记一条**只含参与码与日期**的撤回记录(便于审计样本量变动)→
  若汇总已生成,重跑汇总并注明版本;
- 撤回窗口见知情同意书 §4/§7。

## 4. 收集平台与平台侧数据

平台候选:【问卷星 / 腾讯问卷 / 纸质,待定】。无论选哪个:

- 能关闭的追踪一律关闭(IP、地理位置、设备指纹、微信身份);
- 平台导出完成、核对无误后,**删除平台侧云端数据**;
- 平台如强制收集手机号/微信登录,改用纸质或换平台——资格核验(数学类专业本科生)
  用自报 + 招募渠道保证,不用实名核验。

## 5. 入库前双重检查

1. **自动**:`python3 scripts/check_repo_privacy.py`(已含学号邮箱/个人邮箱域/
   手机号/聊天导出模式与提交元数据检查);
2. **人工**:自由文本理由逐条审查——含自指身份线索(院系、姓名、师承、地名+年级
   组合)的,删除或改写后才可入脱敏层;实验一的教训是"理由原词"也能构成归因面,
   引用时只允许限制性摘录。

提交一律使用仓库化名 git 身份(CONTRIBUTING 已规定);合并一律本地
`git merge --no-ff`(E4 增量后的既定流程)。

## 6. 保存期限与销毁

| 数据 | 期限 | 动作 |
|---|---|---|
| 私有层原始问卷、同意记录、映射表 | 【建议:论文发表后 3 年】 | 到期本机安全删除,登记销毁日期 |
| 脱敏层数据与汇总 | 长期 | 随仓库保留,用于复现 |
| 平台侧云端副本 | 导出核对后即删 | §4 |

## 7. 与既有红线的关系

- 本方案不改动 `DATA_BOUNDARIES.md` 与 `AGENTS.md` 的任何既有红线,只做加法;
- 冻结证据目录不因实验二发生任何写入;
- 实验二评价数据一旦开始回收,判据与材料不得再改(与实验一同一原则,具体判据
  以实验二预注册冻结版为准)。
