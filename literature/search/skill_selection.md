# 检索 Skill 选择记录

## 选择结果

本轮主用 `academic-search` Skill。

选择它的原因不是“名字像学术搜索”，而是它同时提供了本任务真正需要的几种能力：

- 面向计算机科学的来源路由：ACL、arXiv、Semantic Scholar、OpenAlex、Crossref 等；
- DOI、arXiv ID、题名和作者的跨平台去重规则；
- 统一的论文元数据 Schema；
- 开放获取状态和 PDF 直链核验；
- 明确区分“可公开阅读”和“可重新分发”；
- 合法 OA PDF 下载与文件类型检查；
- 系统综述式的纳排、筛选和停止规则。

## 实际用法

1. 先按计算机科学/NLP 路线设计关键词和来源组合。
2. 用广泛检索发现候选，再用官方页面核对元数据。
3. 对核心候选阅读正文或官方摘要，标记证据层级。
4. 用 DOI、arXiv ID、来源 ID 和题名去重。
5. 对每个 PDF 单独核验许可；没有明确再分发许可的条目只保留链接。
6. 用许可感知 manifest 记录下载、跳过原因和来源。
7. 用独立脚本检查 PDF 文件头、大小、SHA-256 和 manifest 一致性。

## 没有让 Skill 替代的判断

Skill 可以帮助找文献和整理元数据，但不能自动决定：

- “回答不同”是否真的等于“回答变窄”；
- 通用标注员能否代表数学本科生；
- 个性化对用户是帮助还是限制；
- 输入输出差异是否证明模型内部机制；
- 一篇新论文是否足以推翻或支持本项目的结论。

这些判断仍按项目的五要素筛选、观察/解释分层和研究红线人工复核。

## 技术回退

Skill 自带的 Node 下载器成功生成了 51 条许可感知 manifest，但在部分学术站点的长连接上会停滞。PDF 本体随后由仓库内的超时、重试、断点和分段下载脚本完成；许可判定和跳过规则没有放宽。该回退过程及校验脚本一并保留，避免把一次本机下载结果当成不可复核的黑箱。
